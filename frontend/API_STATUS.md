# وضعیت اتصال فرانت‌اند چکاد به Backend

این سند بر اساس سورس مخزن در زمان پیاده‌سازی نسخه عمومی تهیه شده است. وجود مدل دیتابیس به‌معنی وجود endpoint عمومی نیست.

## فناوری و معماری موجود

- Next.js 14.2.5، React 18.3.1، TypeScript 5.5.4
- App Router در مسیر `frontend/app`
- Tailwind CSS 3.4.10
- RTL و Vazirmatn از قبل در layout وجود داشتند.
- Gateway مسیرهای `/api/people/`، `/api/content/`، `/api/application/` و `/api/auth/` را به سرویس مربوط هدایت می‌کند.
- فرانت‌اند از `NEXT_PUBLIC_API_BASE=/api` استفاده می‌کند.

## Endpointهای واقعی مورد استفاده

| Method | Path عمومی | سرویس | کاربرد |
|---|---|---|---|
| GET | `/api/people/mentors` | people-service | فهرست مشاوران عمومی؛ فیلتر اختیاری `field=physics|computer` |
| GET | `/api/people/tutors` | people-service | فهرست مدرسان عمومی؛ فیلتر اختیاری `field=physics|computer` |
| GET | `/api/content/` | content-service | محتوای عمومی به شکل key/value؛ در این فاز برای فهرست مقاله و آزمون کافی نیست |

فهرست افراد فقط داده‌هایی را نمایش می‌دهد که API برمی‌گرداند؛ پروفایل خالی یا ناموجود با Empty State نشان داده می‌شود. در مدل فعلی تصویر عمومی افراد وجود ندارد، بنابراین کارت‌ها از نشان حرف اول نام استفاده می‌کنند.

## Endpointهای موردنیاز اما پیاده‌سازی‌نشده

### application-service
- `POST /mentorship-applications`: ایجاد درخواست منتورینگ
- `POST /tutoring-applications`: ایجاد درخواست کلاس خصوصی
- قراردادهای Request/Response، احراز رضایت، سیاست نگهداری داده و کنترل نرخ درخواست باید مشخص شوند.
- `GET /admin/stats` موجود است ولی عمومی نیست و برای وب‌سایت عمومی استفاده نمی‌شود.

### people-service
- در صورت نیاز محصول، فیلد تصویر عمومی و پروفایل قابل‌نمایش با سوابق قابل‌تأیید اضافه شود.
- وضعیت فعلی: `GET /mentors`، `GET /mentors/{id}`، `GET /tutors` و `GET /tutors/{id}` در backend وجود دارد. در این فاز فقط فهرست‌های عمومی استفاده شده‌اند.

### content-service
- قرارداد ساختاریافته برای مقاله‌ها، دسته‌بندی‌ها، نویسندگان، slug، تاریخ انتشار، زمان مطالعه و تصاویر شاخص.
- endpoint فهرست و جزئیات مقاله.
- endpoint مربوط به فهرست و جزئیات آزمون، وضعیت ثبت‌نام و اطلاعات تقویم آزمون‌ها.

## رفتار رابط کاربری

- هیچ درخواست منتورینگ یا کلاس خصوصی از سمت مرورگر ارسال نمی‌شود؛ API عمومی ثبت درخواست وجود ندارد.
- فرم‌ها دو مرحله‌ای و دارای اعتبارسنجی اولیه‌اند؛ هنگام Submit پیام روشن عدم ارسال نشان می‌دهند.
- هیچ آزمون، مقاله، مدرس، مشاور، مدال، نظر دانش‌آموز، آمار یا اطلاعات تماس ساختگی نمایش داده نمی‌شود.
- بخش‌های خالی با Empty State نمایش داده می‌شوند.
- جزئیات پکیج منتورینگ فقط در `lib/mentorship-config.ts` به‌عنوان پیشنهاد داخلی و با `approvedForPublicDisplay: false` نگهداری می‌شود.

## CI و کنترل کیفیت

- `.github/workflows/frontend-ci.yml` برای اجرای TypeScript validation و Next.js production build روی push به شاخه پیاده‌سازی و Pull Request به `main` اضافه شده است.
- در زمان تهیه این سند، GitHub برای commit پیاده‌سازی هنوز status checkای برنگردانده است؛ بنابراین نتیجه Build تأییدشده محسوب نمی‌شود.
- برای اجرای نهایی lint، ابتدا باید تنظیمات و وابستگی ESLint پروژه تعیین شوند؛ این پروژه در نسخه اولیه پیکربندی lint نداشت.

## نکات پیش از Production

1. قرارداد API درخواست‌ها و سیاست امنیت/حریم خصوصی را طراحی و پیاده‌سازی کنید.
2. فرم‌ها را فقط پس از تکمیل API، تأیید سیاست حریم خصوصی و تست end-to-end فعال کنید.
3. endpointهای ساختاریافته آزمون و مقاله را اضافه کنید.
4. ایمیل، تلفن، شبکه‌های اجتماعی، لوگو و تصاویر رسمی را پس از تأیید مالک محصول اضافه کنید.
5. برای صفحات جزئیات از داده واقعی و slugهای منتشرشده استفاده شود.
6. تست بصری در موبایل، تبلت و دسکتاپ و تست مسیرهای فرم پس از اتصال Backend انجام شود.
